# Decisions Log

Choices made without asking (the owner is away during the build). Newest at the bottom of each section.

## Project
- **Name: STORMDRAIN.** Original setting: a kid in a yellow raincoat descends into storm drains during an endless storm.
- **Toolchain:** Vite 8, TypeScript 7 (native compiler), Vitest 5, Playwright 1.63 — latest at build time. No runtime deps.
- **Base path `./`** instead of `/<repo>/` so GitHub Pages works whatever the repository is named.
- **Git identity:** repo-local `user.name`/`user.email` set to the owner so commits are attributed correctly.

## Display & controls
- **Internal resolution 384×192 (2:1).** iPhone 15 landscape safe area is ≈734×372 pt (Dynamic Island and home
  indicator insets), aspect ≈1.97, so 2:1 fills it with minimal letterbox at ≈1.9× scale. Nearest-neighbor
  scaling on a DPR-sized canvas (not CSS `image-rendering`) for consistent crisp pixels in WebKit.
- **Whole canvas lives inside the safe area**, so the HUD can never be clipped by the Dynamic Island.
- **Menus are drawn in the canvas** (consistent pixel look) using our own hit-tested widgets on pointer-up;
  only text entry (seed, save import/export) uses a DOM modal because iOS needs a real input for the keyboard.
- **Single-size rooms (13×7 tiles)** — no large/L-shaped rooms; keeps generation, camera and templates simple.
- **Display scale:** a whole-number device-pixel scale is used when it costs ≤ 10 % of the image size, otherwise a fractional nearest-neighbour scale (iPhone 15 safe area → ≈5.73 device px per game px, filling it).
- **Move stick:** floating, 24 px radius, 14 % deadzone, full output at 85 % of the radius (so top speed doesn't need the thumb pinned on the rim), origin follows the thumb past the rim (never "runs out"), 7° axis magnet so straight walking is easy.
- **Shoot stick:** commits after 3 px of travel; 4-way snap with ~11° hysteresis so diagonals don't flicker; keeps its last direction while held near the centre. A tap shorter than one tick still fires once.
- **Touch HUD layout:** pause top-right, placeholder minimap left of it, active + bomb stacked down the right edge, consumable on the left margin; base size 24 game px (≈46 pt), scaled by Settings (75–150 %).
- **Perf overlay on phones:** three-finger tap (no Backquote key on iOS).
- **Portrait pauses the run:** rotating to portrait shows the rotate card and opens the pause overlay, so returning to landscape never drops you straight into action. While portrait, pointer-downs and menu keys are ignored (the hidden pause menu must not be pressable through the card).
- **Stick hints:** faint MOVE/SHOOT rings at the resting spots on touch devices until the sticks are first used; keyboard players get a one-line hint instead.

## Architecture
- **Simulation is headless** (`src/sim` has no DOM), so the stress test and the play-bot run in Vitest at full speed.
- **Beams are traced by a virtual projectile** running the same motion modifiers as real projectiles — this is what
  makes every modifier work with the Storm Lance/lasers without special cases.
- **Content auto-discovery via `import.meta.glob`** so content can be added in parallel without merge conflicts.
- **RNG:** sfc32 core with splitmix32 seeding; `fork(label)` derives a child from (state, label) without advancing the parent, so adding a fork never shifts existing sequences.
- **Pools are dense arrays** (live items first, free tail = free list); releasing swaps with the last live item, so iterate backwards when releasing inside a loop.
- **Events are consumed per step:** `sim.step()` first discards what the previous step left (already drained); events emitted between ticks (debug hooks) survive into the next drain. The run scene drains after every tick into particles/shake (render) and sounds (audio).
- **Scenes never import each other**; navigation goes through `App.nav` built in `main.ts` (no circular imports).
- **Test room** lives in `src/content/testRoom.ts` (outside `content/rooms/`) with test-only markers `@` (start) and `D` (dummy).
- **`CharacterDef` starts minimal** (id, name, desc, stats, redMax, sprite); `content/characters/wren.ts` already does `export default [WREN]` for the Phase 2 registry.
- **Settings are in-memory in Phase 1**; they will persist inside the Phase 4 `stormdrain.meta` envelope instead of creating a legacy key now.
- **`saveRunNow()`** stub lives in `src/meta/save.ts` and is already called on pause and on background (visibilitychange / pagehide / blur).
- **Phase 2A data layer:** `src/sim/types.ts` holds every content shape (items, effects, enemies, bosses, phases, characters, chapters, synergies, sets, achievements, familiars, drop tables, pools, room types). `RoomTemplate` and floor layouts are deliberately NOT defined there (the floor generator owns them).
- **Effects come in two families:** persistent (stat, mod, carrier, familiar, flag, trigger) are *derived* from what is held and rebuilt by `recomputePlayer` whenever the inventory changes; instant (heal, hearts, pickups, hook) run once. Running a persistent effect from a use/trigger makes it temporary (its `duration`, else until leaving the room). This gives "+damage for the room" actives and "on hurt: +speed for 5 s" triggers without special code.
- **One-time pickup effects only for fresh copies:** a health-up's container is granted when a fresh copy is first taken; swapped-out actives/trinkets are marked not-fresh so swapping back and forth can't farm hearts or pickups. Recomputes never re-run instants.
- **Recompute builds NEW trigger arrays** so an effect that changes items in the middle of a trigger loop can't corrupt the loop; nesting is capped at depth 3.
- **Trigger chance = chance + luck × luckScale, clamped to maxChance,** rolled on the seeded combatRng (replayable).
- **`recomputeAttack(player)` stub** (`sim/attack/recomputeAttack.ts`) is called after every recompute; mods/carriers/familiars are already aggregated into `player.loadout` (stacks + summed params + sources) for the attack pipeline (part B). *(2B: it now builds `player.attack`, the AttackProfile.)*
- **Hooks get an `api` object** (`HookCtx.api`) instead of importing sim modules, so `content/hooks/*.ts` only import `sim/hooks.ts` and the registry → hooks → sim → registry cycle can't happen. Character mechanics that live in the attack pipeline register placeholder hooks (`wren.luckyMarble`) so content validation can check every reference today.
- **Drop tables are a content registry too** (`src/content/drops/*.ts`, `DropTableDef`), rolled on the run-level `lootRng` (added to World next to combatRng). Luck multiplies the "nothing" weight by (1 − luck × table.luck), floored at 20 %.
- **Test-room pedestal picks use their own `room-items` stream** so the offered items never depend on play. `registerItem()` exists for tests only (ad-hoc items must be registered because recompute looks items up by id).
- **`CharacterDef` grew into the full shape:** `hearts: HeartSpec` (half hearts) replaces the Phase 1 `redMax`; `Player.red` / `Player.redMax` stay as getters over `player.health`.
- **Stand-ins for parallel work:** `sim/roomSpawns.ts` (explicit pickup/pedestal placements) is a small local format the floor generator may replace with RoomTemplate markers; `Sim.roomCleared()` / `floorStarted()` / `loadRoom(layout, spawns)` and `World.onSecretWallBombed` are the hooks the floor code should call/set. The ROOMS and MUSIC registries are TODO slots in `content/registry.ts`.
- **New GameEvents** (`pickup, land, loot, item, chest, denied, heal, heartBreak, nova, bombPlaced, explosion, tileHit, tileBreak, activeUse, charged, triggered`) are documented in `engine/events.ts`; the 'hurt' event now carries half hearts lost (a) and the damage source (b).
- **Phase 2C — one Hittable interface** (`sim/hittable.ts`): enemies, dummies and breakable tiles share `hurt(dmg, source, kx, ky)` / `applyStatus(kind, duration, power, source)`. Tiles get one pre-made `TileTarget` adapter per cell so queries never allocate. `hurt` takes a knockback IMPULSE vector (px/s, divided by mass) rather than a direction + strength: the shot pipeline already has the velocity. Sources are small ints (`SRC_*`) that decide kill credit.
- **`applyStatus('knockback', duration, power)`** has no direction argument, so it pushes along the direction of the target's LAST hit (remembered by `hurt`) and dazes for `duration`; call it after `hurt`.
- **Enemies are data + a shared behaviour library.** A def picks ONE movement kind, up to 4 attacks and on-death effects; every behaviour declares its params as `[default, min, max]`, the compiler fills defaults and clamps, and validation reports unknown / out-of-range params. Adding an enemy never needs code.
- **Killing only flags `dead`;** a sweep releases the pool slot after the enemy update and at the end of the step. Explosions, DOT ticks and death effects all kill from inside loops, and a swap-remove would skip or double-visit entities.
- **Behaviour details:** burrowers tunnel under rocks and pits (walls only) but may only surface on open floor (the first version got stuck behind pits). Hoppers pick and validate their landing spot at the crouch, so the telegraph shows a committed jump; airborne they cross pits and rocks. Flyers only meet the walls. Sideways dashers that can't line up (blocked by a prop) side-step for a moment. Wall crawlers move along the room's inset perimeter and ignore the grid. Fear replaces most movements with a flee; hop/burrow/teleport/turret/wall-crawl handle it themselves.
- **Status stacking:** re-applying keeps the LONGER timer and the STRONGER power (no intensity stacking, so fast-firing poison doesn't multiply); burn thaws / freeze extinguishes; charm and fear replace each other; all durations × `resist` and capped at 10 s; resist < 0.75 (bosses) turns freeze into a slow. Poison ticks every 0.5 s (2.5 dmg), burn every 0.3 s (2 dmg); DOT ticks don't white-flash (the tint and particles show it) and credit the player.
- **Charm** = the enemy targets the nearest non-charmed enemy; its contact, shots, trail, shockwaves and minions are allied (×5 damage per half heart to enemies) and never hurt the player. Charmed enemies still count for the room clear. **Frozen kills shatter** into 6 allied ice shards (so freeze builds reward finishing frozen enemies).
- **Champions:** 4 % base + 1 % per luck point, capped at 20 %, rolled on combatRng at spawn (one roll for "champion?", a second weighted pick only on success). Seven data-driven variants in `content/champions/core.ts` (order matters for seeded rolls). Phantom = faded (intangible, harmless) 32 % of a 2.6 s cycle, clearly visible as translucent. Champions get a coloured silhouette outline + glow and roll the extra 'champion' table (Golden drops 3-5 coins instead).
- **Player contact shove (revises the 2A "nothing moves the player" rule):** the task asked for player knockback; we apply it ONLY for enemy contact damage, as a short ≈8 px shove apart that decays in ~0.15 s, so Wren isn't left standing inside the thing that hit her. Shots, explosions and hazards still never move her, and a finger on a button still never moves her.
- **Enemy shot fairness:** shots hit with 0.8 × Wren's radius (grazes forgiven), pop on contact even during i-frames (no double hits from one shot), rocks stop them and pits don't (like marbles). Lobs only hurt where they land and show a pulsing marker there. Fresh enemies are inactive and harmless for 0.4 s (spawn poof). Every attack has a wind-up telegraph (half-alpha white blink + squash or a wind-up frame, plus a sound).
- **Training-yard arena:** F or the bell button (left margin, under the consumable button, hidden during a wave) calls 4-6 random chapter 1 enemies (+1 every other wave, max 8) at free floor ≥ 56 px from Wren; a room with `e`/`E` markers puts one enemy on each. Doors are always drawn in the yard and get iron bars while a wave lives. Clearing calls the existing `roomCleared()` (active +1, 'roomClear' triggers) and rolls the existing 'roomClear' table at the open floor nearest the centre.
- **Stand-in: `src/content/chapters/gutterways.ts`** (ChapterDef for chapter 1 with the 8-enemy pool, empty boss pools, music id 'gutterways') exists because content validation requires enemy chapters to exist and the arena needs a pool; the floor / chapter integration may take it over (keep the id).
- **Marbles hit enemies in `projectiles.ts`** (damage + knockback impulse along the shot) as a stand-in until the attack pipeline (2B) owns shot hits; `combat.damageArea` (bombs, Ember novas, hooks) now hurts enemies too. *(2B: done — `projectiles.ts` is gone; every player attack hits through the Hittable interface in `sim/attack/`.)*
- **Hit-stop is presentation-only:** the run scene skips 2 sim steps after a big kill (1 for a champion) — the sim itself never pauses, so headless runs are unaffected; it never skips a step with a pending button edge. No damage numbers.

## Attack pipeline (Phase 2B)
- **Motion is heading-based.** A shot has a heading, a non-accumulating offset (wavy) and a speed; velocity is derived each step, and a motion hook may override the velocity for one step (orbits, corkscrews, circling). Size and damage are base × per-step multipliers reset before the motion hooks, so grow and shrink (and any future size modifiers) compose instead of fighting.
- **Beams run the same hooks at a virtual speed of 240 px/s** (dt = 4 px / 240 per trace step), so a homing lance bends exactly like a projectile would at that speed, wavy lasers draw the same wave, and a bouncing beam reflects with the same wall hooks. The lance re-traces every tick from Wren's current position in the direction it was released.
- **The Storm Lance passes through rocks and props (and burns the crates / urns / fires it crosses); only walls stop it. Lasers stop at rocks and props (cracking breakable ones) unless phasing.** The lance is the signature item and "to the far wall" should always be true; lasers keep rocks meaningful as cover. Lasers pierce enemies by default, so `pierce` on beams adds damage (+12 % per stack) instead of pierce count.
- **Lance numbers:** charge 1 s × 3 / fire rate, clamped 0.25-2 s (a snap removes float drift so it is exactly 60 ticks at 3/s); releasing early fizzles (no damage); no new charge while the beam is live; 12 px × √(shot size / 3) wide; 0.5 s; a 1.1 × damage tick every 3 ticks per target (10 ticks ≈ 38 damage per target at Wren's base damage — everything in the line dies); status / chain / explode hooks on every 3rd tick so a lance with explode doesn't carpet-bomb.
- **Implicit modifier stacks:** the boomerang carrier (primary or rider) adds a `boomerang` stack, the bomb rider adds `explode` stacks, the `spectral` flag adds `phase`. Riders then need no special motion code of their own.
- **Carriers stack like modifiers** (duplicate carrier items = copies: thicker lances, more orbit blades…); `Loadout.carrierStacks` counts them. **Marble as a rider** (a marble carrier held under another primary — no such item yet) adds a half-strength companion marble to every volley, so even that pair merges instead of doing nothing.
- **Charge rider:** 0.9 s × 3 / fire rate; release = damage × 0.5 → 2.5 (+0.5 per extra copy) and size × 0.8 → 1.8; a laser primary instead fires a charged burst of 1-6 lasers; the lance overcharges to 200 % (up to ×1.5 damage, ×1.6 width, ×1.5 life).
- **The fire cadence reads the live fire rate** (`periodMul / stats.fireRate`) while every other number comes from the profile built on inventory changes, so the exact-cadence tests (and debug stat tweaks) keep working.
- **Wren's Lucky Marble (`wren.luckyMarble`)** is implemented in the pipeline: starting a wave (an uncleared room) arms a keeper; the next player volley's main shot deals ×3, is ×1.6 bigger, pierces everything and uses a gilded star style (a chime and a sparkle). Riders and beams honour it too (a keeper lance beam deals ×3).
- **Split:** 1 + stacks children (max 6), half damage each, 0.75 size, fanned 100° beyond the target (which they ignore at first); they split again only while their depth < min(3, stacks). Children that don't fit the pool merge into fewer bigger ones; if none fit, the target takes their damage at once. Beams fork their trace instead (1 + stacks, max 5, depth ≤ 2).
- **Chain:** 1 + stacks jumps within 52 + 8·stacks px, 60 % damage each, re-applying the shot's status effects (not split / explode — no recursion). 32 arcs per tick; over the cap, half the remaining damage lands on the first target.
- **Player blasts never hurt the player.** Explosions from shots are queued (64, overlapping ones merge), at most 6 per tick and 48 per 0.5 s (the rest wait a tick); plain `explode` blasts only crack props, bomb-rider blasts break rocks like bombs (and can reveal secret walls).
- **Player puddles are allied creep** (the enemy creep pool, cap 48): they hurt enemies every 0.5 s and never the player; a new puddle on top of an existing one refreshes and grows it instead (≤ 4 new puddles per tick).
- **Status chances:** poison, burn and slow always apply (the status rules already prevent intensity stacking); freeze (22 %), charm (14 %) and fear (18 %) are chances that grow +13 / +8 / +10 % per extra stack and +2 % per luck. Charmed enemies are left out of the target snapshot (your attacks leave your new friends alone).
- **orbitPlayer on beams = a rotating ring** of 1 + stacks evenly spaced beams (3 + 0.6·stacks rad/s). On projectiles the ring widens to 20 + 7·stacks px, then creeps outward (12 px/s) so orbiting shots still sweep the room.
- **circleFirst:** one lap around the owner (0.45 s + 0.1 s per extra stack) that doesn't use up range, then the shot launches along the aim; beams spin one full circle in 0.2 s + 0.05 s per stack before settling on the aim.
- **Spiral became a corkscrew** (loops around a centre that advances along the heading, widening to 10 + 3·stacks px): a pure outward spiral stays next to the player and dies on the nearest wall — useless in 13 × 7 rooms.
- **Orbit rider:** 1 + stacks blades (max 8), radius 22 px, 0.9 × damage, re-hit every 12 ticks, swat hostile enemy shots, inherit every hit modifier, and fire a mini (scale 0.4) version of the primary with every player volley (never recursively).
- **Familiars:** stable slots (anchors stay valid), follower chain along a breadcrumb trail of the player's path (13 px apart), orbiters swat shots. Shooters use the player's profile at their `attackScale` and fire with the player's volleys when their own cooldown allows — on charge releases always (they "charged with you"). Content: Lamplet, Paper Boat (shooters), Bottlecap Beetle (orbiting blocker, contact damage).
- **Guardrail for beams: a shared trace budget** of 5000 points per tick. With 48 lances each gets ≈ 100 points and a coarser step (≤ 12 px) so it still reaches as far; fewer fork points. The absurd "every modifier ×5 + lance + orbit" build averages ≈ 0.3 ms per step (≈ 2.5 ms on the busiest ticks) in node.
- **The event queue grew to 1024** so absurd builds (dozens of beams hitting everything on one tick) don't drop sounds; lance hit sparks are limited to 6 events per tick.
- **ShotStyle:** base colour from the character (new optional `CharacterDef.shotColor`), carrier tint (lance electric blue replaces it), modifier colours weighted by stacks (≤ 80 %), rim from the dominant modifier, up to 3 accent pixels, shape from the carrier then the strongest shaped modifier, up to 3 trails. Sprites are cached per style object (WeakMap + numeric keys — no string building per frame). Many overlapping lances dim their glows (1.25 / √n) so the room doesn't wash out to white.
- **Costumes:** `CostumeDef` gained `frames ('dir' | 'anim'), fps, glow, sparks, additive`; items / sets take one def or an array (`CostumeSpec`). The Storm Lance wears a crackling aura (generated jagged ring, 3 frames, additive, sparks) and glowing storm eyes (per facing).
- **Audio `param`:** `AudioOut.play(name, pan, volume, param)` passes a level to the recipe (`voice.param`) so the lance charge hum rises in pitch as it fills; attack sounds live in `audio/sfxAttack.ts` (prefixed names).
- **Shot 'splash' events carry the style colour** in `id`, so bursts come out in the shot's colours.
- **Training yard:** a sixth pedestal at (3, 1) offers a random attack carrier ('starter-attack'); showy modifier items are tagged 'starter-special' (offered next to flight / the Ember heart). Two part-A tests counting five pedestals now count six. *(2D: the yard now has three rotating treasure pedestals, a rotating attack pedestal, both actives and a wave bell — see below.)*
- **Items (Phase 2B):** 7 carrier items (Storm Lance q4, Neon Tube, Rusty Boomerang, Broken Oar, Firecracker Pouch, Coiled Spring, Tin Pinwheel), 3 familiar items and one item per modifier (29) with generated "token" icons (a marble in the modifier's colour with a 5 × 5 glyph) — every carrier and modifier can be picked up and stacked. *(2D: the token items were replaced by the curated starter set below.)*

## Phase 2 verification (independent pass over parts A-D)
- **Method: a composition detector, not eyeballing.** Every trajectory-shaping modifier (spawn + motion stages) and every pair of them was fired on every primary in a fixed scene and the whole run fingerprinted; a pair whose fingerprint equals one of its parts means one modifier silently did nothing. The original code had 56 such cases; now 0. It is a unit test (`tests/attack-compose.test.ts`), plus a delivery matrix: every hit / status modifier must land through marble, lance, laser, boomerang, swipe, orbit blade and familiar (77/77).
- **Homing chose targets it could never reach.** It locked onto the NEAREST enemy, usually one beside or behind the shot, inside its turning circle, and circled it forever: homing marbles did 4 damage where plain ones did 49, homing ×3 lances and lasers did 0. Homing now picks the cheapest REACHABLE target: distance + turn radius × bearing, skipping anything deep inside a turning circle and anything the shot just hit (piercing shots move on). A shot with nothing ahead still U-turns (Backwards Cap's design). Beam trace cursors remember what they passed through so a homing lance bends on to the next enemy.
- **Tiny planet (orbitPlayer) used to overwrite every other motion modifier** (homing, wavy, spiral) and ate bounces. It now composes: homing picks a target and the orbit WHIPS OUT to it as its sweep comes up on it (then settles back) — orbiting shots lash at passing enemies instead of either ignoring them or abandoning the orbit; a heading turn made by another hook (a wall bounce) tilts the orbit and fades; wavy makes the ring breathe. Homing and the orbit cooperate through a shared ShotState flag (`F_ORBITING`), documented in §4.4 — the one deliberate modifier-to-modifier contract. A wall bounce clears the one-step velocity override so the reflected heading applies at once.
- **Spiral is an offset on top of the path** (after orbitPlayer in the motion order): along the heading (so wavy, homing and bounce still steer it) or around the orbit an earlier hook set (a corkscrewing tiny planet). Its loops close up on a boomerang's way home so the catch still works.
- **Beams: accelerate / decelerate / phase did nothing on the lance.** A beam has no speed to show, so accelerate tapers it into a thinner, harder-hitting whip (width ÷√k, damage ×(1 + 0.5(k − 1))) and decelerate flares it out (×√(1/k)) and makes it linger (+20 % lance / +25 % laser life per stack, via `prepare` adjusting the profile). Phase on the lance (which already passes rocks) adds +15 % damage per stack. Beam traces use a uniform dt (step / 240) so these speed changes shape a beam without weakening homing / boomerang bends.
- **A beam orbit ring swallowed extra / back / side shots** (the ring had max(count, 1 + stacks) beams): now every spec gets `stacks` copies, spaced evenly — Tiny Moon + Twin Straws on a lance is a spinning X of four.
- **Explode items were swallowed by the bomb rider** (its blast took max(explode, bomb) numbers, so explode items added nothing to it). Now each explode item on top adds +5 px and +0.25 × damage to the bomb blast (shots, beam blasts along the lance, swipe tips).
- **Beam rate limits could be reset by a crowd:** with more targets than the 16 slots a new target evicted a live slot and its old target was hit again at once (up to 3× damage). One slot per target the snapshot can hold (96), never taken from a live target.
- **Smaller fixes:** orbit blades re-run the init hooks when the profile is rebuilt (a new item used to drop e.g. the knockback multiplier); a swipe that doesn't fit the swipe pool puts its damage on the volley's previous swipe or its crescent; circle-first beams finish their spin within 60 % of their life (a laser used to die mid-spin, never facing the aim); laser-rider side zaps skip ring / spin beam hooks (they stay aimed); the player's own shot blasts spare charmed enemies like every other player attack (placed bombs and novas still hurt everything); a debug / menu enemy spawned without a position goes to the nearest free floor cell (it used to land on the yard's training dummy).
- **Cosmetic events have their own cap:** an every-item build emitted up to ~700 events in one tick (bounce sparks, splashes). `EventQueue.emitFx` skips cosmetic events once the queue holds 256, so kills / hurts / items always get in and render / audio never chew through hundreds of bursts per tick.
- **Headless perf (every item ×3, 20 s of waves, node):** 0.17–0.48 ms per tick on average depending on the primary, 1.5–2.5 ms on busy lance ticks with 48 beams; the worst tick is the very first lance release (≈ 13-16 ms, JIT warm-up). A unit test keeps it under 4 ms average with no event overflow, and checks the absurd build is deterministic.
- **Render perf was the real bottleneck:** with 48 tapered lances WebKit spent ~79 ms per render (4-7 fps) — beams whose width varies (grow, shrink, accelerate, decelerate) were stroked one trace step at a time, thousands of calls per frame. A varying-width segment is now ONE filled outline per pass (exact taper), an even one ONE stroked path; with more than 12 lances or 2000 lance points each lance drops to lite passes (one glow, core, one strand) and the cores / strands dim with the crowd (the room used to wash out white). Result: ~9 ms and 44-63 fps in software WebKit. Beams are clipped to the room so glows never spill over the HUD margins. `__SD.perf` exposes the loop's update / render ms; an e2e test keeps the absurd build's render under 45 ms.
- **Verified and left alone:** Tin / Ember heart order with real pickups, spill-over and the Ember nova, i-frames against shots and contact, charm (never hurts the player, left out of your targets) and fear (runs away, stops attacking), champions, bombs, chests and pickups — existing tests plus new end-to-end ones (`tests/verify-rules.test.ts`); a 24-run × 40 s randomized bot fuzz with random loadouts kept every health / position / counter invariant. Telegraphs (white blink + squash / wind-up frames), pickups (pop, bounce, sparkle) and the Storm Lance (blinding flash, beam to the far wall, lightning, sparks) were checked in WebKit screenshots at 852×393 and read well.

## Feel & presentation
- **Movement:** 96 px/s top speed, constant-rate vector approach (1200 px/s² accel → top speed in 0.08 s / 5 ticks, 960 decel → stops in 0.1 s with a ≈4 px slide, 1.75× boost when reversing). Chosen over exponential smoothing for crisp starts and stops. (Verification retune: the first pass reached top speed in 0.064 s, a touch twitchy for analog thumbs; the target window is 0.08–0.12 s to start and ≈0.1 s to stop, enforced by a unit test.)
- **Collision:** circle vs the closest point of each blocking tile — slides smoothly along walls and rounds rock corners. Pits are inset 3.5 px (you can stand on the lip), rocks 1 px.
- **Marbles have height:** they fly at eye height (z = 7), collide at their ground position (the shadow), then drop with gravity after their range and splash. Tile hits use 70 % of the radius so shots graze past rock corners.
- **Fire cadence:** the cooldown carries its fractional remainder (3/s is exactly every 20 ticks) and never banks shots while idle; a press fires on the same tick.
- **Shot juice:** alternating left/right eye offset (±2 px), 25 % of player velocity inherited, 1 px recoil, muzzle sparkle, splash ring + droplets, dummy flash + spring nudge + health bar, pop burst + shake.
- **Splash at the marble's height:** the `splash` event carries the marble's height (`b`), so wall/target splashes burst where the marble visibly was (eye height) with a 1-frame white-hot flash, and droplets rain down to the floor ring.
- **Marble halo:** additive glow (radius 7, red-heavy `255,158,56`, peak 0.8). Weaker/yellower halos added up to grey on the blue stone instead of reading as warm light.
- **Marble colour:** warm candle-gold/amber so it pops against blue-grey stone and stays distinct from Wren's lemon-yellow coat.
- **Training dummies regrow** 2.4 s after popping (the stake stays behind) so the test room never runs out of targets. Phase 1 has no game over: after the death animation a fresh room starts.
- **Render interpolation:** player and marbles are drawn between the last two ticks by the loop's alpha, so 120/144 Hz displays stay smooth with a 60 Hz sim.
- **Font:** original 5 px variable-width pixel font, uppercase only (lowercase input renders as uppercase). `W` uses a pointed bottom (`.#.#.`) — the first design read as `H`. Baked multi-line text is centred per line.
- **Frozen scenes render at alpha 1:** scenes under an overlay (the run under pause) draw their latest tick instead of interpolating, so nothing shimmers on >60 Hz screens while paused.
- **Stats:** fire rate is linear to 5 shots/s, then `5 + 4·ln(1 + (x−5)/4)` — keeps growing (stacking should snowball) but each item adds less. Move speed is capped at 2× the character's base. Other hard clamps in `STAT_RULES`.
- **Health:** containers + bonus hearts ≤ 12 hearts (two HUD rows). Damage spills from one heart into the next (a full-heart hit on half a Tin heart also takes half a red one). No knockback on the player — a hit never moves you (also keeps "a finger on a button never moves you" true).
- **Starter items are small, single-stat bumps** (+1 damage, +0.75 shots/s, +14 px/s, +45 range & +25 shot speed, +1 heart container with a full heal, +1 luck) so later items have room to feel big. Names and art are original (Brick Chip, Wind-Up Crank, Puddle Jumpers, Kite String, Thermos of Soup, Four-Leaf Button). A starter kit adds one of each other kind: Jar of Lightning (2-room shockwave), Picnic Basket (25 s timed, drops snacks), Leaky Umbrella (flight), Candle Stub (+1 Ember heart), Fridge Magnet and Worn Bandage (trinkets), Fizz Tonic and Lucky Sticker (consumables).
- **Pickup feel:** loot pops up 70–105 px/s with 28–62 px/s outward, bounces once or twice, slides to rest in ~0.5 s, can't be taken for 0.3 s so you see it land. Things you can't take (red hearts at full health, coins at 99, spark cells without a chargeable active) get shoved ahead of you; chests are heavy. Overlapping loot separates softly. Lucky Coin = 1 coin + 0.5 luck. A small Spark Cell gives +1 room charge or a quarter of a timed item's charge.
- **Magnet** pulls coins/hearts/keys/bombs/sparks within 64 px — never chests or trinkets/consumables (no accidental swaps).
- **Pedestals are solid** little pillars; touching one takes the item. After a swap the old item waits until you step away (no ping-pong). Items bob above the pedestal with a warm glow; Wren faces the camera and holds a new item overhead for 0.8 s.
- **Trinket/consumable swap drops the OLDEST** into the world as a pickup (not fresh, must step off it first).
- **Bombs:** 1.4 s fuse that blinks faster and faster (with fuse sparks), 40 px blast, 50 damage, 1 heart to the player, tiles within 22 px of the centre (≈ the 3×3 cells around it), pickups/bombs pushed up to 68 px away, chain reaction after 0.12 s. The bomb spawns under Wren and only gets nudged once she has stepped off it. Secret walls: the explosion reports the wall's door slot when it lands within 34 px of a wall centre.
- **Room props:** crates take 2 shots (cracked look after the first), urns 1, fires 4 (flame shrinks per hit); counting hits (not damage) keeps them readable. Fires are solid braziers that burn on contact (½ heart); spikes hurt ½ heart underfoot (feet ≥3 px inside the tile) unless flying. Flying crosses pits and ignores spikes; props still block.
- **Explosion flash** is a warm white full-screen flash (≤ 45 %), softened when screen shake is turned down.
- **Room background uses positional hashing** for per-cell variety so breaking a crate doesn't reshuffle floor stones/decals; debris marks (rubble, planks, shards, ash) are drawn procedurally per cell.
- **HUD placement:** hearts top-left (6 per row), counters under them, charge bar just left of the active button, trinkets beside the consumable button, banner in the top band. Refusal notices ("NO BOMBS", "NEEDS A KEY") replace the room label in the top band instead of floating over the room.
- **Training yard:** the test room now holds a row of crates/urns/tinted rock/metal along the top wall, a dummy column on the right, a fire + spikes corner guarding a satchel and a lockbox, five pedestals (two random stat items, one special passive, both actives) and every pickup kind. Popping all three dummies at once counts as a room clear (recharges room actives).

## Floor generator (side track, merged after Phase 2)
- **The map is always a tree:** growth only fills a cell that touches exactly one room, so every two adjacent rooms share a door and there are no loops or 2×2 blobs. Room count = 8 + ⌊(floor − 1)·10/12⌋ + 0..1, never below special rooms + 6 (≈ 8.9 main-map rooms on floor 1, ≈ 18.5 on floor 13, plus the secret rooms).
- **The boss is at least 3 rooms from the start** (4 when the floor has 13+ rooms) on the farthest dead end. A failed attempt retries; every 400 failures adds a room, then drops optional special rooms, so generation always finishes (worst case ≈ 240 attempts, average ≈ 4, well under 2 ms).
- **Special rooms:** treasure every floor (locked from floor 3 = chapter 2), shop except on floors 12-13 (locked from floor 2 since polish batch 1), miniboss 35 % from floor 2 (polish batch 1: none on floor 1), challenge arena 30 % from floor 2, cursed room 25 %. "Dead end" counts regular doors only.
- **The secret room gets a bombable wall to every neighbour,** special rooms included, so it can add a hidden second entrance to a special room (even a locked treasure room). The deep secret room touches exactly one normal room and nothing special. Hint walls: 40 % (deep secret 25 %), per side.
- **Broker's Nook:** a free cell next to the boss room is reserved (touching no other room; secret rooms can never touch it); `openNook(layout)` adds the room later and its template is picked in advance with the rest.
- **Hidden-route grate** only on the main track before floor 12 (boss trapdoors keep the current track, so the alt track has nowhere to route to): secret room 55 %, boss room 45 %, default chance 0.4, only when the caller passes `allowAltNext` (unlock rules stay the caller's). *(Polish batch 1: the run adds a start-room grate on main floor 1 that restarts floor 1 on the alt track.)*
- **Curses:** chance min(0.5, 0.04 + 0.035·(floor − 1)), one curse per floor, picked evenly from `opts.cursePool`; `forceCurse` wins over `curses`.
- **Determinism:** randomness comes from `floorRng` forks named `plan`, `layout`, `curse`, `hints`, `route` and `templates`, and every roll is always made, so changing an option never changes the map. `FLOORGEN_VERSION = 1` with a pinned fingerprint of 650 layouts catches accidental generator changes. *(Polish batch 1: version 2 — locked shops, no floor-1 miniboss, the curse id `unknown` → `leak`; re-pinned once.)*
- **Door masks:** bit N = 1, E = 2, S = 4, W = 8; each room has `doors` (every connection) with `secretDoors`, `hints` and `lockedDoors` as subsets; a locked treasure door is marked on both sides. `dist` counts regular doors; a secret room's dist is its nearest neighbour's + 1.
- **Template rules:** the tile just inside each door ((6,0), (12,3), (6,6), (0,3)) must be `.`, so any template fits any door mask and any mirroring; no enemy spawn next to those tiles; every walkable tile reachable on foot; the four doors joined by a path without spikes or fire; per-type marker rules; the centre walkable in start / boss / miniboss / challenge rooms; at most 10 enemy spawns.
- **Template picking:** weight by closeness to a target difficulty (1.0 on floor 1 up to 3.0 on floor 13, + up to 0.35 on the way to the boss), ×3 for chapter-specific templates, ×0.15 for one already used on the floor; candidates sorted by id; each room gets a random mirroring (flip 0..3). Because picks depend on the whole template set, adding rooms changes which templates existing seeds get — run saves must store the whole `FloorLayout` (plain JSON, ≈ 3-5 KB).
- **Minimap:** a 'Mapped' level (outline only, no icon) sits between Unknown and Seen for layout-revealing items; special icons show once a room is Seen; a secret room is never revealed from outside through its hidden wall; the Lost Map curse only hides the drawing (the map keeps updating underneath). *(Polish batch 1: the curse — now the Soggy Map — leaves the VISITED rooms on the map instead of a '?'.)*
- **Final-boss markers** are `thunderhead`, `nestmother` and `undertow`; floor 13 accepts either track.

## Music & SFX library (side track, merged after Phase 2)
- **Track ids:** chapter loops are `ch_<chapterId>` (`CHAPTER_MUSIC` in `src/audio/music/ids.ts`); boss themes `boss_floodgate` (chapters 1-2), `boss_pressure` (3-4), `boss_undercurrent` (5-6) via `BOSS_MUSIC` / `bossMusicFor`; finals `final_thunderhead` / `final_nestmother` / `final_undertow` (`FINAL_MUSIC`); roles in `MUSIC` (title, shop, secret, miniboss, victory / game-over jingles, floor / boss-intro / item stingers). 27 original tracks; a recurring title motif returns in Eye of the Storm, Old Thunderhead, The Undertow and the victory jingle.
- **`MusicTrack` lives in `src/audio/music/types.ts`** (pure, DOM-free), not `src/sim/types.ts`; content files import types and helpers from `src/audio/music`. The track registry is `src/audio/music/registry.ts` (import.meta.glob, throws on duplicate ids, compiles lazily and caches).
- **Pattern language:** scale degrees relative to key / scale (with `'` `,` `#` `b` accidentals and octave marks), absolute notes, chords with `+`, `:n` lengths, `-` holds, `.` rests, `!` / `?` velocity, `~` glide and optional, validated `|` bar lines; drum lanes are one character per step (`x X o + .`). Patterns may also be arrays of bars.
- **Meters:** shuffle / swing feels use a triplet grid (stepsPerBeat 3); 6/8 is beatsPerBar 2 × stepsPerBeat 6; 7/8 is beatsPerBar 7 × stepsPerBeat 2 with bpm counting eighths.
- **Scheduler:** 25 ms setInterval, 120 ms lookahead, step times from the absolute step index (no drift); steps more than 50 ms late are skipped instead of burst-played; the interval only runs while something plays and stops while the page is hidden.
- **Crossfades, pause / resume and stingers** are all built from starting / fading TrackPlayers; pause resumes from the start of the current bar; a stinger's `then` starts the next track on the exact sample the stinger ends; a disposed player cuts its still-ringing long notes through a fixed-size SourceRing (no per-note allocation).
- **`app.audio.music` exists on both WebAudio and NullAudio** (a MusicDirector that records the wanted track until an AudioContext is attached on the first gesture), so game code never checks for audio support.
- **SFX library** self-registers through `registerSfx()` when engine.ts imports it; built-in recipes win on a name clash and `SHADOWED_SFX` (kept empty by a test) exposes clashes. Recipes gained an optional `maxVoices` enforced by `SfxPlayer`; name lookups use own-property checks (a name like 'constructor' can't hit Object.prototype).
- **Loudness:** per-track gain trim (validated 0..2.5), `MUSIC_TRIM` 0.45 and a gentle bus compressor (−12 dB, 2.5:1) keep music under the SFX at default volumes; every track and sfx was measured by offline rendering in headless Chromium (Playwright WebKit on Windows has no Web Audio): no clipping, tracks within ≈ 1.3 dB at about −22 dBFS, the loudest sfx peaks ≈ −4 dBFS. Nobody has listened to it yet — taste-level tuning (trims, presets) is open.
- **The music noise buffer is deterministic** (LCG), so drum textures sound identical every session.

## Saving & PWA (side track, merged after Phase 2)
- **Checksum** = FNV-1a 32-bit over `'<v>:' + JSON.stringify(data)` — it covers the version too, and is verified by re-serialising the parsed data (stable, because the stored text was itself produced by JSON.stringify).
- **Write order:** the previous good save is copied to `<key>.bak`, then the new one is written; out of space → drop `.corrupt` and `.bak`, retry once; an identical save is skipped; the first write without a `load()` still backs up a valid save already there.
- **Loading:** a damaged main save falls back to `.bak` and the main key is repaired; the damaged text is kept under `<key>.corrupt`. A save from a newer version makes the slot read-only, so an old cached build (service worker!) never overwrites newer progress.
- **Meta v0 = the Phase 1 prototype layout** (flat Settings fields plus flat id lists), never shipped, so the upgrade path is exercised from day one; `META_VERSION = 1`.
- **Unknown fields survive:** unknown top-level keys go into `MetaState.extra`, unknown keys in settings / stats / collection / bestiary / daily entries stay on those objects, unknown unlock kinds are kept as sets; all are written back. Id-keyed maps use null-prototype objects so ids like `__proto__` are harmless.
- **Unlocks are Sets in memory, sorted arrays on disk**, so saves are deterministic and unchanged saves can be skipped.
- **MetaStore saving:** important changes (settings, unlocks, achievements, run start / end, daily, import, reset) save at the end of the tick; frequent ones (kills, collection / bestiary counts, stats, counters, play time) at most every 5 s; a failed write retries after 10 s; listeners are notified once per tick with a reused change summary. `collectItem()` / `killEnemy()` also update lifetime items / kills / boss kills; `recordRunEnd` resets the win streak on death or quit; daily results are one per UTC date, newest 400.
- **Achievement counters are an open map** (any id works, content can add counters without a schema change); the known ones default to 0.
- **Settings adapters** (`toRuntimeSettings` / `fromRuntimeSettings`) match `meta/settings.ts` structurally instead of importing it, so the two can change independently; `showFps` and `leftHanded` exist only in `MetaSettings` so far.
- **Run saves are plain JSON only,** ≤ 1,000,000 characters: Map, Set, Date, typed arrays and class instances are rejected; shared (non-cyclic) references are allowed; undefined properties are dropped like optional fields.
- **Export code** = `SD1:` + base64url(UTF-8 of the same checksummed envelope) with body `{ app, at, meta: {v, data}, run?: {v, data} }`. Import ignores whitespace and accepts standard base64; a run that can't be upgraded is dropped with a warning while progress still imports.
- **The service-worker plugin is `scripts/sw-plugin.mjs` with a `.d.mts`** (Vite 8 warned about extensionless imports in the config chain and tsconfig doesn't allow `.ts` extensions); its pure logic is in `src/pwa/precache.ts` and `swSource.ts`. `sw.js` is generated in `closeBundle` by scanning dist/ (so public/ files are covered); version = hash of every file plus the worker template; the cache name includes the scope so two deployments on one origin don't delete each other's caches.
- **Worker behaviour:** precache with `cache: 'reload'` (bypasses stale HTTP caches such as GitHub Pages' 10-minute max-age); redirected responses stored as clean copies (WebKit); navigations get the cached index.html; other files cache-first with runtime caching; lookups ignore `Vary` — `vite preview` sends `Vary: Origin` and the page's crossorigin module request carries an Origin header, so the cached script was never matched and the game couldn't boot offline (found in headless Chromium, covered by a test).
- **Quiet updates:** the worker never activates itself early; `register.ts` tells a freshly installed update to take over, never reloads the page, and checks for updates when the app returns to the foreground at most once an hour; registered with `updateViaCache: 'none'`, only in production and on secure origins.
- **Icons** are opaque RGB (iOS home-screen icons must not be transparent): Wren's yellow hood and a glowing marble in front of a drain pipe, drawn on 32 / 30 / 40 px grids scaled by whole numbers; the maskable icon keeps the eyes and marble in the 80 % safe zone (tested); a test fails if the committed PNGs no longer match the art. Manifest colours `#000000`; no manifest `id`, so it defaults to `start_url` and stays unique per sub-path deployment.
- **`requestPersistentStorage()`** (`navigator.storage.persist`) is a best-effort guard against Safari evicting the site's storage. The run save and the meta save share the ≈ 5 MB localStorage quota; when full, each only drops its own backup.

## Floor runs (Phase 3A)
- **New Run starts a real run** (seed, Wren, floor 1, main track); the training yard moved behind the debug menu (CHEATS → TRAINING YARD, `__SD.debug.yard()`). The Phase 2 e2e specs start in the yard (New Run, then `yard()`), so they keep testing what they were written for.
- **The run lives in `src/sim/run`** (a `Run` owned by the Sim, `new Sim({ run })` / `Sim.newRun`) instead of a UI-side controller: headless tests, the bot and saves all get the same code path. `RunData` is plain JSON from the start (no Maps / classes), so a snapshot is a `JSON.stringify`.
- **Everything a floor offers is pre-rolled** from `floorRng(seed, floor, track).fork('contents')` when the floor is generated — including the ENEMY ids per marker (champion rolls stay on combatRng because luck affects them). Same seed = same rooms, enemies, items, chests and shop stock whatever the player does; only drops and in-room randomness depend on play. Items never repeat within a floor (no cross-floor exclusion: that would make floor N depend on floor N−1's route); pools fall back (secret → treasure, …) because the content pools are still thin; quality weights 1 / 1 / 1 / 0.7 / 0.35. *(3B: items SEEN earlier in the run are now left out too — the task asked for it — so later floors' items depend on what was seen; one fork per room keeps new rolls from shifting other rooms.)*
- **Snapshots are checkpoints at room entries.** Every transition stores `JSON.stringify({ run, world, player })` just before the room is built; `Sim.fromSnapshot` restores world + player and runs the very same `enterCurrent()`. Resuming therefore replays the entry exactly (spawns, champion rolls, floor-start triggers) and play continues identically — a test steps the original and the restored sim side by side for 900 ticks through several rooms and the next floor. Progress inside the current room is not saved (resuming = walking back into that room), which also keeps saves small (a few KB) and blocks mid-fight save-scumming. To make "identical" true, familiars are rebuilt in canonical slot order at every room entry (quietly, no poof), and temporary effects are stored by value, trigger cooldowns by list position.
- **Doors are walked into, not stepped through:** the room walls stay solid; pushing the stick (> 0.3) toward a wall while the feet touch it within ±10 px of the door centre uses the door. No doorway tiles means nothing else (shots, beams, pickups, enemies) can wander into a doorway. A 0.35 s cooldown after each entry prevents ping-pong; 0.5 s of spawn safety (`world.safeT`, no damage at all) covers the arrival.
- **Door frames follow the neighbour** (a boss door looks like one from both sides; inside a special room its doors wear its frame; a plain door inside the boss room is a boss door). Nine kinds + the blasted-hole "secret" kind, 24×16 sprites (4 px of decoration each side), padlocked leaf as a seventh frame.
- **Magpie's Stall is locked with a key from floor 2; the Keepsake Room from floor 3** (owner requirement: keys open locked doors, shops and locked chests — this replaces the first choice, "the shop is never locked"). Floor 1's shop stays open so a new run can spend its first coins; `lockedOnFloor(type, floor)` in the generator decides, both sides of the one regular door get the lock bit, and the door draws the padlocked leaf of its own (shop) frame. Key drops are not retuned here (a later balance batch re-targets the economy for the new key demand).
- **Shop stock = items on priced pedestals** (the shop pool, any kind; 10 / 12 / 15 / 20 / 25 coins by quality, trinkets 8, consumables 5 + quality). Pickups for sale, Magpie herself, restocks and theft come with the full shop (M2). *(3B: Magpie, goods and the jar are in; restocks and theft are not.)* Broker's Nook deals cost heart containers (1, quality 4: 2) and never take the last heart (with no containers left you'd need a bonus heart to stay alive).

Hints: the generator's `hints` bits, or every hidden wall with the `seeSecrets` flag — a faint breathing crack (fainter for deep secrets) and an occasional drip.

- **Curse of the Maze:** 20 % of regular-door transitions go to a random VISITED room (never an unknown one — being thrown into unexplored rooms would bypass locks and secrets), rolled on combatRng; "THE MAZE SHIFTS..." + teleport sound. **Deluge:** accel × 0.35, decel × 0.2 unless flying, plus rain. **Unknown:** the heart row becomes '? ???'. **Blind:** '?' icons on pedestals and floor items; the pickup banner still names what you took. *(Polish batch 1: renamed — the Shifting Pipes ("THE PIPES SHIFT..."), the Fogged Glass (items show up close) — and the Unknown replaced by the Leaky Roof; see "Polish batch 1".)*
- **The big map pauses the run** (an overlay scene): on a phone the thumb that taps the map is off the sticks, so a running game would mean free hits; Tab opens / closes it on desktop, any tap closes it.
- **Placeholder bosses until M2's framework** *(3B: replaced by real BossDefs; the placeholder stays only as the fallback when no boss content of a kind exists at all)*: the boss room's 'B' holds the strongest chapter enemy that actually moves (turrets / idlers make a dull boss) at HP clamp(hp × 6, 90, 160) × (1 + 0.12 per floor after the first), scale 1.5; minibosses a weighted pick at clamp(hp × 3.5, 45, 80), scale 1.3. The boss reward comes from the boss pool (then treasure).
- **Trapdoor:** appears at the centre when the boss dies, opens over 0.8 s, and only drops the player once she has stepped off it (standing on the spot when it opens mustn't yank you down mid-loot). Floor 12's boss wins the run ("CLEAR SKIES") until the Undertow / endings exist; the hidden-route grate is not placed yet (runs pass `allowAltNext: false`: track switching is M2's).
- **Challenge rooms fight two waves** *(3B: a pressure plate starts three waves)*; only the last counts as a room clear (one reward drop, one active charge) and the reward (its i / c markers) appears then.
- **Broker's Nook odds** *(3B: 25 %, + 35 % without damage — the task's numbers)*: 55 % after a floor without damage, 20 % otherwise, rolled on the floor stream (`fork('nook')`) so the same seed + clean play always gets it.
- **Room transition presentation:** the sim swaps rooms at once (headless semantics stay simple); the scene freezes stepping for 0.25 s and slides the previous frame's room image out while the new room slides in (the room rect of the back buffer is copied each run frame — one 240×144 drawImage). The trapdoor closes an iris on the old image, the new floor opens under it, then the floor card ('CHAPTER N · NAME', floor, curse) shows for 2.8 s. Death shows a card after the death animation; a tap, any key or 8 s returns to the title (run saves / Continue are Phase 4).
- **Chapter looks = patterns × palettes:** 6 floor patterns (flagstone, checker, earth, slab, plate, hex) and 5 wall patterns (brick, blocks, timber, panel, paper), mostly generated by code, recoloured by 19 palette keys per chapter, plus 3 decals + 1 wall trim + an ambience per chapter. Cheaper than 12 hand-drawn tilesets and every chapter still reads differently (a test checks floor colours and pattern variety). Obstacles (crates, urns, spikes, fire, metal, tinted rocks) keep one look so they read the same everywhere.
- **Darkness is one offscreen canvas** with pre-rendered radial light sprites punched out (player r 54, fires, item pedestals, the trapdoor) — no per-frame gradients; the `darkVision` flag (Waxen set) ignores it.
- **Minimap:** compact 6×5 px cells centred on the current room with special rooms as coloured dots (icons don't fit 5×4 px); the big map uses 15×11 cells, 5×5 icons and door connectors. Both are cached canvases keyed by numbers (layout identity, `version`, room count, Lost Map) — no key strings per frame.
- **Music wiring:** title theme; chapter loop on a run's first floor; the floor sting into the next chapter loop on each trapdoor; boss intro sting → boss theme in an uncleared boss room (back to the chapter loop on the clear); miniboss / shop / secret themes; quality-4 item fanfare; game-over / victory jingles; the pause overlay muffles.
- **Debug:** the CHEATS grid became 4 × 5 (24 px buttons) to fit skip floor, reveal map, go to boss, next curse, training yard and new run; `__SD.debug.runAt(floor, track, curse, seed)` restarts the run scene anywhere (e2e renders all 12 chapters and all 6 curses with it). Debug teleports walk in through the room's first door (standing in the middle could put Wren on a pedestal or the boss).

## Bosses, special rooms, routes & endings (Phase 3B)
- **A boss is an Enemy with a brain.** `enemy.boss` (BossState) replaces the movement / attack step; everything else — hits through the Hittable interface, statuses, knockback, collisions, the renderer, kill credit, the bestiary events — is the enemy code. Each phase compiles into a synthetic EnemyDef (baseline movement + enemy-library attacks) so a phase's in-between behaviour reuses the movement kinds and attacks; the big moves are a separate pattern library. Chosen over a parallel boss entity type, which would have duplicated collision, statuses and rendering.
- **Patterns are data + tiny state machines** (15 kinds, params `[default, min, max]` like the enemy behaviours, validated). Every pattern opens with a telegraph (flash + squash + pose + 'bossTell'); timers are divided by the phase's `pace`, shot speeds multiplied by √pace (faster phases stay dodgeable). Baseline movement is limited to stateless kinds (idle, wander, chase, chasePath, float, orbitPlayer, keepDistance, hop); burrow / teleport / charge are patterns so they can clean up when interrupted.
- **Phases:** the FIGHT's HP (summed over split parts) decides the phase; a new phase = a 1.1 s invulnerable roar (hits 'tink'), a white flash, a colour wash that ramps in, fresh attack timers, a faster pace, then its `enter` pattern (split / shields / summon / hazard). A single blow is capped just past the next threshold, so no phase is ever skipped (a charged Storm Lance can't blow through a phase change). Phase 0's `enter` runs after the intro. The brain starts after the spawn poof.
- **Split bosses share one fight:** each part is a full boss enemy with its own BossState (same def and phase); parts die individually; only the last plays the death sequence. The HP bar shows the sum.
- **Shields are tethered enemies** (`enemy.anchor`): they orbit their boss, hide when it hides and die with it — a generic enemy feature rather than a new movement kind, so the content agents' MOVE_KINDS list stays untouched.
- **Death sequence in the sim, slow motion in the scene:** the last part turns `dying` (untouchable, still alive for the room clear), kills its adds, fizzles hostile shots, pops 'bossBoom's for 2.4 s (positions from combatRng — deterministic), then the real kill. The run scene plays the first 1.5 s at half speed by skipping every other tick (presentation only, like hit-stop); headless tests see the same ticks.
- **Boss sprites are painted, not typed:** `content/sprites/paint.ts` composes big sprites from shapes with an automatic outline; 32-56 px bosses as hand-typed strings were error-prone. Boss sprites anchor in the lower body (`anchorY`) so the collision circle covers what you see; the shadow goes under the sprite; the world renderer clips to the room so a boss by the top wall never draws over the HUD.
- **Boss HP:** 260-300 for the chapter 1 bosses (≈ 25-30 s at Wren's base damage), 120 for the miniboss, 700-900 for the finals (placeholders, sized for a floor-12 build). A boss borrowed by a chapter without its own (every chapter but the Gutterways for now) gets +14 % HP per floor past its home chapter. Contact damage 1 (finals 2). Status resist 0.5 / miniboss 0.65 / finals 0.4.
- **Selection:** `bossPool` = the union rule (explicit list ∪ bosses naming the chapter); an empty chapter borrows every boss of the kind (better than a scaled-up rat while chapters 2-6 have no bosses yet). The pick uses its own fork (`floorRng(...).fork('boss' | 'miniboss')`) and avoids the previous floor's boss of the same chapter, recomputed from that floor's seed (no cross-floor state).
- **Rewards:** boss = pedestal (boss pool, rolled with the floor) + a heart + the 'bossSpill' table + the trapdoor; miniboss = the 'minibossReward' table (2-3 useful things) + a heart, no pedestal (35 % of floors have one — a pedestal each would flood the run with items).
- **Magpie perches on the top wall** instead of standing in the room: no collision, never blocks a slot or a path. Same for the Moth Broker. Old Pell stands in the room because he IS the trade (a pedestal prop showing his item).
- **Shop layout:** at most 5 slots; 2-3 items (the first slots in marker order, i.e. the top row of the generic shop) and pickups for sale in the rest. Goods are only sold when they can be used (no buying a heart at full health) and are handed over directly (no physics on a bought pickup). Price tags turn red when unaffordable.
- **Old Pell trades 3 keys for an item** (the task offered "one of your passives or 3 keys"): taking a passive away needs a UI to choose which and could remove a set piece by surprise; keys are a clear, visible price and give keys a second use. The 'haggler' flag makes it 2.
- **Donation jar:** always in the shop; one coin every 0.28 s while you lean on it (a bump shouldn't empty your purse), luck +0.5 at 5 / 15 / 30 / 50 / 75 / 99 coins donated this run; `counters.donated` is kept for unlocks.
- **Gumball Gambler:** 12 % of normal rooms, outcomes on the loot stream (the same seed + the same plays = the same prizes), 46 % nothing; a blast breaks it for 3-6 coins. Solid props only go where the room stays connected without their cell (BFS check at placement).
- **Nook price with no containers:** 3 Tin hearts per container, and never the last bonus heart (it would kill her).
- **Rain Barrel Arena:** calm until the pressure plate (you choose when to fight; you may leave before pressing), then the doors lock through all three waves with a 1 s breather between them.
- **Hidden routes:** `altRouteAllowed` = main track, floor < 12, and floors 10-11 only with 'ending1' (their next floor is chapter 6); without Ending 1 an alt-track trapdoor into chapter 6 lands on the main track. The grate must be bombed open (the crack and drips are the hint), and in the boss room it only appears after the boss. *(Polish batch 1: main floor 1's start room may hold one too → the alt floor 1; it seals when she leaves the start room.)*
- **Endings flow:** a final boss's kill ends the run with its ending unless both 'ending1' and 'ending2' are unlocked — then a whirlpool (floor 13, The Undertow) and a skylight (take the ending now) appear, so a player hunting Ending 3 can still bank the one in front of them. The floor-13 boss is picked by the layout's 'undertow' key. Run options stand in for the meta flags until M3 (`RunOptions.unlocked`: item ids and 'ending1' / 'ending2'). The victory card shows the ending's title and line (a stub for M4).
- **Unlocks:** `RunOptions.unlocked` is one list of ids (items + route flags) rather than separate fields; the run turns it into its locked-item list once at the start (`lockedItemIds`), so the meta snapshot never changes mid-run.
- **Snapshot version 2:** RunData gained unlocked / seen / ending, RoomState its special-room state; the run save isn't wired yet (Phase 4), so v1 snapshots need no migration.
- **Debug:** CHEATS got BOSS: <name> (cycle) and FIGHT BOSS (any boss in the current room, yard included); `__SD.debug.boss(id)`, `bosses()`, `runAt(..., unlocked)`; `Sim.startBossFight(id)`; `registerBoss(def)` for tests.

## Saving, meta progress, achievements, transformations (Phase 4A)
- **One save service:** `meta/save.ts` `GameSave` owns storage, MetaStore, RunSaveStore, the AchievementEngine and the MetaTracker (built once in main.ts as `app.save`). The old module-level `saveRunNow()` stays for the lifecycle / pause call sites and reaches it through `installGameSave`.
- **The run save is the room-entry checkpoint** (`Sim.snapshot()`, as designed in 3A): written at run start / Continue, after every room entry, on pause, on background and before quitting to the title. Resuming inside a room = walking back into it (no mid-fight save-scumming, saves stay ≈ 20 KB and < 0.5 ms).
- **Death clears the run save the moment the player dies** (not after the game-over card), so closing the app during the death animation can't bring the run back; a win clears it at 'runEnd'. The save host (`RunScene.savableSim()`) never offers a dead / won run or the yard.
- **Quit to title keeps the run** (Continue on the title). **New Run over a saved run abandons it without a prompt** (counted as a 'quit', which ends the win streak): with a saved run the title's main button is CONTINUE and NEW RUN sits below it.
- **Run save version = `RUN_SNAPSHOT_VERSION` (2), no migrations:** nothing older was ever saved; an older / unknown snapshot loads as damaged and is dropped with a toast; a newer version's run is left alone (read-only slot). A damaged latest save continues from the previous room's `.bak` copy.
- **Settings persist through the meta save**; the Phase 1 `SettingsStore` stays the runtime bus (initialised from `MetaSettings`, every change written back — a no-op when unchanged).
- **Notices and achievements are toasts** over the bottom wall (one at a time, 3.2 s, never a button, never over the room's interior); save notices that last the whole session (a newer version's save, no storage) are a line on the title instead.
- **Meta tracking lives in `meta/`, not the sim** (the sim may not import meta): `MetaTracker` reads the tick's GameEvents after each Sim step plus a few polled values (items / coins / familiars held); the yard is never tracked.
- **Bosses count once per fight** (from `world.counters.bossKills` + `world.boss`), so split bosses aren't counted per part and debug kills that skip the death sequence still count. The item collection's "seen" comes from the run's own `seen` list (what the pools already exclude), skipped under the Curse of the Blind.
- **A clean floor** = its exit was taken (or the run won there) with no change to `world.counters.hurts` since it began; the Thorn Room toll counts as a hit.
- **Endings unlock their route flags on being reached** ('ending1'…, in the `endings` set) whatever the achievement content says; the ending achievements exist for the toast and add the same flag.
- **Achievement conditions:** a lifetime COUNTER (stat, meta counter or keyed count like `killed.<id>`) or a run EVENT with optional `id` / exact `value` / `atLeast` filters. The old `{ counter, atLeast }` shape stays valid (`kind` optional), so content written against Phase 2A types still compiles.
- **Unlocked = in the unlock set OR the named achievement is earned:** an item or character added later that names an already-earned achievement is unlocked at once; `syncRewards()` at boot writes those rewards into the sets quietly.
- **Six starter items start locked** (Party Popper, Ice-Cube Tray, Paper Valentine, Geode, Wick Wisp, Rooftop Rod) so item gating is real from day one; ~50 others stay in the pools. Drop tables respect the run's locks too (`world.lockedItems`); the training yard offers everything.
- **Transformations are permanent for the run** once earned (the design's "new look + strong bonus"), saved in `PlayerSnap.sets`; losing a set item doesn't undo them. Their instant effects (hearts…) and hook run once, at the transformation, after the recompute (no re-entrancy).
- **Distinct items count:** sets need `need` DIFFERENT items, and synergy tag counts count different items; a duplicate never completes a set or a tag requirement on its own.
- **Synergies switch off when a requirement fails** and back on when it holds again; their banner, instant effects and hook run only the first time per run (`PlayerSnap.synergiesSeen`), so swapping items can't farm them.
- **Style overrides apply after the composed ShotStyle** (colour takes 75 % of the body and becomes the first accent, a shape replaces the composed one, a trail goes first, glow adds); a transformation's costume layers replace item layers of the same slot.
- **Transformation banner over the top of the room** (3.2 s, translucent, sparkles, with the item fanfare + the 'transformation' sfx + a light pillar); the SYNERGY pill takes the room label's place in the top band.
- **Minibosses get the boss-intro sting** too (then their theme), like bosses.
- **Daily runs:** the tracker already records a daily result when a run is started with `{ date, seed }` (score = floor × 1000 + kills × 10 + a win bonus); the daily-run UI is a later Phase 4 item. *(4B: done — see "Menus & screens"; the attempt is now claimed when the run starts.)*

## Menus & screens (Phase 4B)
- **Every menu is canvas-drawn; the DOM is only for typing.** Seed entry and save import / export are a small DOM modal layer (`ui/domModal.ts`) over the canvas: iOS needs a real input for its keyboard, paste and select-all. The modal is pixel-styled to match, placed inside the game image, and the only place where text selection is allowed. The game ignores keys and gestures aimed at it; a canvas scene blocks the game's buttons meanwhile.
- **The field is focused synchronously inside the tap.** iOS only raises the keyboard for a focus made during a user gesture; the modal opens from the button's pointerup, so it focuses right there (a 60 ms retry covers browsers that refuse while the canvas holds pointer capture).
- **Button height 27 game px** (was 24-26). The Playwright Safari profile (and Safari with toolbars) shows the game at ≈ 1.67 CSS px per game px, so 26 px was 43 pt; 27 px is 45 pt there and ≈ 55 pt in the home-screen app. An e2e test checks every visible button of every menu page is >= 44 CSS px tall on both iPhone profiles.
- **Title layout: the play column inside the arch, pages on the walls.** CONTINUE / NEW RUN / DAILY RUN / ENTER SEED in the middle (the arch's dark interior makes them read); COLLECTION and BESTIARY tiles on the left wall, ACHIEVEMENTS and STATS on the right (a 16 px icon over a small label), SETTINGS as a slim button in the top-right corner. Nine buttons fit at thumb size without paging, and Wren and her first marble stay visible.
- **New Run goes through character select** (as do Daily Run and Enter Seed): even with one character it shows her stats and mechanic, and it is where locked characters tease their unlocks. `__SD.debug.newRun()` / the debug menu still start a run directly (last character, random seed). Existing e2e specs tap START after New Run.
- **Character select supports N characters:** a strip of 26 px slots (paged with arrows past 8), the pick shown big with stat bars. Locked characters are black silhouettes with a padlock, '???' for a name and the unlock hint (their achievement's description, '???' for hidden ones); their stats stay hidden. `CharacterDef.mechanicDesc` (optional) describes the mechanic in words, because `mechanic` is a hook id.
- **Seed codes: 8 characters, `ABCD 1234`.** Any 8 of A-Z / 0-9 are valid (spaces, dashes and case are ignored); random and daily codes avoid look-alikes (no I, O, 0, 1). The sim seed is the hash of the code. The code itself is stored in `RunData.seedInfo` (optional, additive), because a hash can't be turned back into the code the player typed, and Continue / the pause menu / game over must show it. Debug runs without a code show their numeric seed as `#1A2B3C4D`.
- **Seeded runs are practice** (the task asked to decide): a typed seed, RETRY SEED after a death, or an unscored daily replay earns no single-run achievements (event conditions: items held, clean floors, chapters, bosses, endings, character wins) and doesn't unlock endings or routes, because a known seed can be rehearsed or shared. Lifetime stats, counters (and the counter achievements they reach — kills, deaths, secrets found), the collection and the bestiary still count: that is honest play. The seed modal, character select, pause menu and ending screen say "PRACTICE". *(Polish batch 1: typed codes and dailies also roll against the canonical fresh-save unlock snapshot, so a code is the same run on every save.)*
- **Retry = the same code as practice.** Restarting a random run's seed after dying hands you a known map, so it follows the seeded rule; retrying a scored daily replays it unscored. *(Polish batch 1: a retry also reuses the run's stored unlock snapshot.)*
- **Daily run: one scored attempt per UTC day, claimed at the start.** The result is recorded when the daily run starts (`done: false`), updated every floor and finished at death / victory. Quitting, abandoning or closing the app can't buy a second scored try. A later daily that day is an unscored replay with the same code (the character select says "ALREADY PLAYED TODAY · PRACTICE"). The player picks the character (the result records it) rather than being given a fixed one: only one character exists so far, and the daily score is personal. *(Polish batch 1: the date is checked again at START and while the character select is open, so a daily never straddles UTC midnight.)*
- **Import only from the title.** Import replaces the run save, and a live run would overwrite it at its next room entry; in a run the button is disabled with a note. Export works anywhere (it exports the room-entry checkpoint). Importing asks for confirmation with a summary (achievements, items, runs, wins, time played, whether a run comes along) and rebuilds the achievement engine so imported achievements aren't earned twice.
- **Sliders: tap to jump, drag to slide, commit on release.** A drag previews volumes live and writes the setting once when the finger lifts (writing the meta save every tick of a drag would be wasteful). A quick tap presses and releases between two ticks, so the slider's release handler takes the value too. The keyboard nudges by the step; Enter on a slider does nothing.
- **Left-handed swaps the thumb columns, not everything.** The move stick goes to the right half and the shoot stick to the left; active and bomb move down the left margin below the hearts and counters, and the consumable (and the yard bell) moves under pause on the right. Pause and the minimap stay top-right, a system corner rather than a thumb zone. Mirroring those too would put them over the hearts. The HUD puts the charge bar and trinket icons on the side facing the room.
- **Keyboard navigation is spatial.** Arrows move to the nearest button that way (distance along the axis + 2 × the sideways offset), Tab cycles, Enter / Space press, Esc / Backspace go back; focus brackets show only while the keyboard is the last input device, so touch players never see them. Grid pages (collection, bestiary) move the selection through the grid, and up from the top row reaches BACK.
- **Game over and endings are overlay scenes over the frozen run** (`over`, `ending`), not a card drawn by the run scene; `presentation().ending` still reports 'death' / 'win' for the tests. Game over shows what dealt the killing blow. `damagePlayer` gained an optional attacker uid, and creep puddles and shockwaves remember their owner, because the killer's name and sprite make a death legible. Endings get a painted vignette and four lines of original epilogue, typed out and skippable with a tap. They also list what the win unlocked for the first time.
- **Toasts go to the top edge on screens whose buttons run along the bottom** (game over, endings: `Scene.toastsAtTop`). Their titles moved down to leave room for them.
- **Floor card polish:** the band opens from its centre line, the title and floor line slide in from opposite sides, and a track of twelve floor marks (paired by chapter; a thirteenth on floor 13) shows how deep the run is — past floors gold, this one lit (violet on the hidden route).
- **Demo fixtures for screenshots:** `__SD.debug.demoCharacters()` (8 recoloured, locked placeholder characters — enough to page the strip) and `__SD.save.demoProgress()` (sample collection / bestiary / stats / achievements) live in `debug/demo.ts`; the game never calls them.

## Phase 3-4 verification (independent pass over M1-M4)
- **Method: a god-mode explorer, not a checklist.** `tests/helpers/explorer.ts` plays a floor the way a player would reach every room — pushing into doorways, bombing secret walls, using keys, pressing the arena plate, killing through the real damage path (bosses go through phases and their death sequence), taking / buying everything, then the trapdoor, the grate or the whirlpool — and writes every exception, soft-lock, dead door, missing boss / trapdoor or unexpected drop into a report instead of throwing. 200 seeds × floors 1-4 (both tracks through grates), 30 whole runs to all three endings, and 1 221 snapshot forks (120 seeds, real aiming and firing) came out clean after the fixes below. This caught one real divergence (below) and none after it.
- **Fixed: the opened Broker's Nook shared one object with its pre-roll** (`rooms[n] = data.nook`). The live run mutated both, the checkpoint JSON wrote two independent copies, so a restored run's data differed from the original's. The nook room is now a JSON copy.

- **Fixed: a run save with every copy damaged silently removed Continue.** `GameSave.dropDamagedRun()` at boot drops it (text kept as `.corrupt`) and says "SAVED RUN LOST". A meta save that started fresh after damage used to stay damaged on disk until something changed (the "SAVE DAMAGED" toast came back every launch); fresh and migrated meta states are now written back at the end of the first tick.
- **Fixed: a brand-new player was told "GAME UPDATED · RESTART TO PLAY THE NEW VERSION"** on about half of first visits. - **Fixed (wording):** "1 RUNS", "1 ITEMS" and the like in the import summary, the ending's run line and the per-character stats.
- **Fixed (presentation):** the last room's notice followed her through the door ("MAGPIE: NO TOUCHING…" in the next room) — a room entry now clears notices older than the entry tick (the maze's own "THE MAZE SHIFTS…" stays); the boss intro card lingered over a fight that had already ended — it fades at once; empty active / consumable slots and a bomb button with no bombs showed bright placeholder icons that read as items — they are drawn faint (`UiButton.dim`).

The explorer's real-fight warnings (enemies left after 45 s) were all its own dumb steering around metal / rocks, not unreachable enemies.
- **Known, not changed:** toasts slide over the bottom wall and briefly cover the bottom door (by design: never the interior); at 150 % button size the faint resting MOVE / SHOOT hint rings overlap the lowest margin button until the sticks are first used; the title's marble trail still hides behind ENTER SEED (M4's note).

## Test infrastructure & CI (Phase 5)

## Polish batch 1 — critical bugs and unmet hard requirements
- **Stuck burrowers (soft-lock):** an overdue burrower under a rock / pit / barrel steers for the nearest cell it can surface on — a breadth-first ring search over the 13 × 7 grid from its own cell (it tunnels under everything), nearest in a straight line within the first ring that has one, lowest index on ties — cached on the enemy (`Enemy.surfCell`, reset on spawn; no snapshot field, since checkpoints are taken before anything spawns) until it surfaces; a plain Floor cell is the fallback. Hard cap: still down 4 s past its tunnel time, it is put on that cell and starts the normal surfacing (telegraph + 'burrow' event). No new randomness. The old goal, the room's middle, is a barrel or a rock in many templates (the play-bot's 3 soft-locks in ~1,700 runs).
- **No miniboss on floor 1** (`MINIBOSS_MIN_FLOOR = 2`): floor-1 minibosses caused 18 of 112 floor-1 deaths in the balance audit. The plan still draws the roll on floor 1, so its stream keeps its shape.
- **Hidden route to the alt floor 1:** main floor 1's START room gets a cracked hidden-route grate on 50 % of runs (`START_ROUTE_CHANCE`, its own fork `floorRng(seed, 1, 'main').fork('startRoute')` in `makeFloor`, so no existing stream moves; `RunOptions.startRouteChance` for tests). Bombed open and stepped on, it restarts floor 1 on the alt track (`descend(..., 'startGrate', floor)`) with the same seed, inventory and health: the iris and the floor card play, but it is not a cleared floor — no `floorsCleared`, no clean-floor credit; the tracker skips via 'startGrate' (it still counts as a hidden route taken). Leaving the start room by any door or teleport sets its grate to 0 (sealed), so floor 1 can't be looted first and then replayed on the alt track. It lives in the run, not the generator: floorgen works per floor and the run owns the route rules.
- **Grates never sit on a decorative grate tile:** the floor-frame pick moved from render/roomBg.ts into the pure `sim/floorLook.ts` (`floorLookAt`), which both the renderer and `placeGrate` use; the grate also avoids the start room's spawn cell. Grates in secret / boss rooms may move by a cell (their positions were never pre-rolled or saved).
- **Teleport arrivals come through a door:** teleport items (Hopscotch Chalk, Keepsake Sticker…) enter like a visitor — the first regular door (`arrivalSide`), else a secret room's first hidden wall (from inside they are doors). Landing in the middle used to take the Keepsake item (900 / 900 arrivals), press the arena plate (213 / 213) and put her on the boss spawn (every boss / miniboss arrival). A room without any door (none exist) would get `entrySide` -2: the free cell nearest the middle away from markers, pedestals, the plate, exits and ≥ 48 px from foes. Continue replays the same door arrival (it is in the checkpoint).
- **Boss contact during the intro is harmless:** `contact()` skips a boss (or a split part) while its intro card runs (`boss.introT` / `world.boss.introT`); the boss stands still then anyway.
- **No teleport during a boss's death sequence:** `FLOOR_LINKS.canTeleport` (new, reached through `ItemsCTools.canTeleport`) is false while the fight or any boss part is dying, so every teleport item refuses and refunds (Hopscotch Chalk too, without its in-room blink); `queueTeleport` also refuses, and a teleport queued on the tick the death began waits for it to end. `Run.update` now handles the room clear BEFORE a pending teleport, so a teleport on the clearing tick can't lose the trapdoor, the reward or the kill (Brimwell used to come back at full health).
- **The Thorn toll can't be tunnelled:** a burrowed Pip surfaces at the thorns (`mech.resetRoom()`; the room change would surface him anyway) and pays. The toll has its own damage source, `DMG_TOLL` (the game-over screen says "A THORNY DOOR"); it is still paid before the checkpoint and god mode is still exempt.
- **Coin-Op Cocoa refuses when it can give nothing:** full = no red to heal (`canHeal`) or, for a Tin-only character, no room for another half Tin heart (`canAddBonus(health, BONUS_TIN)`) — refused and refunded instead of taking 5 coins. The Rusty Toll Box (the other paid heart) doesn't buy a Tin / Ember heart she can't hold. Both hooks import the pure `sim/health.ts` (it imports nothing, so no registry → hooks → sim cycle).
- **Curses never hide the HUD, and have original names:** darkness = CURSE OF THE BLACKOUT, lostMap = THE SOGGY MAP, maze = THE SHIFTING PIPES, blind = THE FOGGED GLASS, deluge unchanged; the internal ids stay (they are in saves and seeded rolls). The heart-hiding 'unknown' became 'leak', CURSE OF THE LEAKY ROOF: every hit from foes (contact, shots, creep, shockwaves), spikes, fire and blasts costs half a heart more; the Thorn toll and chosen costs (tonics, debug) don't. It keeps the same FLOOR_CURSES slot so seeded curse rolls stay aligned, with a new 7 × 7 icon (a cracked heart with a drop). `migrateCurse` maps a saved 'unknown' (floor curse or forced curse mode) to 'leak' on restore (additive: RUN_SNAPSHOT_VERSION stays 2). The Soggy Map keeps both maps drawn with only the visited rooms (no outlines or icons of rooms seen through doors or revealed by items); the Fogged Glass shows items as '?' until she is within 26 px (the pickup banner still names what she took). The floor card adds a one-line hint of what the curse does (`CURSE_HINTS`); the pause and debug menus show short names (`CURSE_SHORT`).
- **A seed recreates its run:** typed codes ('custom') and dailies start with the CANONICAL unlock snapshot of a fresh save — an empty list: only ungated items roll, no route / ending flags — instead of the player's (`unlocksForRun`, which the run scene uses through `GameSave.unlockedForRun(seed, fixed)`). The same code gives the same floors on every save, before and after any unlock, and the daily is the same run for everyone. The cost: in a seeded run the alt route into chapter 6 and the whirlpool to floor 13 stay closed even for a player who has earned them (seeded runs are practice and can't unlock endings anyway). Random runs keep the player's own unlocks. RETRY SEED passes the finished run's stored `RunData.unlocked` (`RunStart.unlocked`), so the retry is the same run even after a new unlock. The seen-item exclusion is unchanged (same seed + same route = same run).
- **A daily never straddles UTC midnight:** the character select re-checks the date twice a second and, when it rolled over, switches to the new day's daily (code + scored flag, header "NEW DAY!"); `nav.startRun` re-checks too (`rolledOverDaily`), and the title's daily tick refreshes every second. One sitting can no longer claim yesterday's scored daily and then today's.
- **HEALTH in the pause STATS:** a full-width line on top — red hearts as now / max ('2.5/3'), then '+2 TIN' / '+1 EMBER' in their colours; a Tin-only character shows '3 TIN' — then the six stats in two columns of three, 8 px apart (was 9), so everything fits the 384 × 192 panel (a unit test and the e2e check the layout rects: no overlaps, everything inside the panel). Chosen over a 4 + 3 column split because a 114 px column can't hold the longest value ('4.5/5 +2.5 TIN +3.5 EMBER'). The character card labels its heart row HEALTH (her max hearts: red containers, Tin, Ember).
